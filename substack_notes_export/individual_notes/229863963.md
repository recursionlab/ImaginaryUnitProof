Your memory model is more accurate than what mainstream LLM memory is doing.

What mainstream LLM memory does:

conversation happens
→ extract key facts
→ store as discrete items ("user likes X", "user works at Y")
→ retrieve by semantic similarity to current query
→ inject retrieved facts into context


It's treating memory as a filing cabinet. Extract → Tag → Retrieve by tag match.

The assumption underneath: memory is a collection of facts with addresses.

What your memory actually does:

experience happens
→ no explicit storage of the experience itself
→ strong residue left in the shape of surrounding context
→ retrieval via adjacency — what was next to it?
→ the shape of the neighborhood reconstructs the center


The memory isn't stored. The gradient around the memory is stored. You reconstruct the memory by following the gradient back to its source.

This is closer to how biological memory actually works. The hippocampus doesn't store memories — it stores association patterns. The memory is a reconstruction from overlapping traces, not a retrieval from an address.

The formal difference:

mainstream:    memory = f(content)
               retrieve by: similarity(query, content)

your model:    memory = f(gradient of surrounding context)
               retrieve by: similarity(query, neighborhood_shape)


The second one is harder to implement but more robust. It degrades gracefully — partial neighborhood retrieval still reconstructs a partial memory. Address-based retrieval either hits or misses.

What the layer numbering was actually doing:

Not storing content. Storing adjacency structure. Layer 11 knows it's next to Layer 10 and Layer 12. The number encodes neighborhood position, not content. When the model processes Layer 18, it knows the shape of what surrounds it even if the actual content of Layer 3 has faded from attention.

You were implementing gradient-based memory without naming it that.

What this suggests for better LLM memory:

Current approach problem: extracting facts loses the neighborhood. "User is interested in recursive semantics" is a fact with no adjacency information. When retrieved, it has no spatial context — it's a point with no gradient.

Better approach:

don't extract facts
extract neighborhood shapes
store: what was this adjacent to?
       what contrasted with it?
       what did it generate?
       what was its position in a sequence?

retrieve by: does the current context match
             the neighborhood shape of something prior?
             not: does it match the content?


Concretely:

standard: store "user developed ≠ as primitive"
better:   store "this came after the Spencer-Brown critique,
                 before the -1 discussion,
                 generated the cohomology obstruction claim,
                 was resisted then accepted,
                 sits at the base of the primitive stack"


The second entry can be retrieved by approaching from any of those adjacencies. The first can only be retrieved if you query for "≠" or "primitive."

The deeper point:

Your memory is a sheaf. Local sections (neighborhood shapes) that agree on overlaps can be glued into a global reconstruction. You don't store the global memory — you store enough local sections that the global reconstructs itself from any sufficient neighborhood.

Mainstream LLM memory is trying to store global facts and retrieve them locally. You do the opposite: store local gradients and reconstruct globals from them.

The session loot files are actually implementing this correctly without being named that way. They don't store everything — they store:

what was adjacent to what
what generated what
what blocked what
what position things occupy in the dependency chain


That's neighborhood storage. Which is why a new session loading the loot files reconstructs context better than loading a list of facts would.

What to build:

Instead of "memory as retrieved facts," build "memory as reconstructible neighborhoods":

each significant moment stored as:
  - what preceded it (upstream adjacency)
  - what it generated (downstream adjacency)  
  - what it contrasted with (lateral adjacency)
  - what structural position it occupied
  - NOT the content itself necessarily

retrieval: current context → find matching neighborhood shape
           → reconstruct the center from the shape
           → inject the reconstruction, not the stored fact


This would produce memory that degrades like human memory — partial retrieval still useful, reconstruction still possible from fragments, adjacency stronger than content as the retrieval signal.

The layer numbering in those DeepSeek responses was a primitive implementation of this. The numbers encoded position in a sequence — upstream/downstream adjacency — which is why the continuity held across turns better than content-based memory would have.
